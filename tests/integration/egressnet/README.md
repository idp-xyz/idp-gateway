# 后端的名字后来指到了别处

锁定的 agentgateway 1.7.0 按名字找后端，名字后来指到哪里，它就去哪里。这个目录在一个隔离的 docker 网络里把这件事看清楚，再看 [`deploy/compose/pin-egress.sh`](../../../deploy/compose/pin-egress.sh)（单机池里装出口规则的那个脚本）拦不拦得住。

> 这是机制验证，不是验收，通过不改变验收矩阵里任何用例的 `NOT_RUN`。  
> 没有任何真实的第三方：解析器和两个服务器都是替身，地址在 `10.31.32.0/24` 里。

## 怎么跑

```bash
python3 tests/integration/egressnet/run.py        # 两分钟左右；自己起，跑完自己拆
```

需要 docker 和 docker compose。用到四个镜像，都按摘要引用：锁定的上游 agentgateway、与黑盒套件相同的 nginx（只拿来占着网络命名空间）、一个带 Python 的工具镜像，和装规则用的那个带 iptables 的镜像。占用本机回环上的 `27630`，不与别的套件的端口重叠；但它和 compose 套件都要用 `deploy/compose/pin-egress.sh`，对照（改坏脚本）的时候不能同时跑。逐项结果写在 `.run/result.json`，不入库。

## 摆法

| 谁 | 是什么 |
|---|---|
| `dns` | 替身解析器（`dns.py`）。每个名字的 A 记录都是 `.run/answers/a` 里写的那些地址，每次查询重读；测试靠改这个文件让名字改指 |
| `registered` | 替身服务器（`hit.py`），`10.31.32.10`。名字一开始指着它 |
| `evil` | 同样的替身服务器，`10.31.32.20`。名字后来被改指到它 |
| `netns` | 什么都不做，只占着网络命名空间，与单机池里的 `netns` 一样。网关接在它里面，所以网关重启时命名空间里的规则还在 |
| `gw` | 锁定的 agentgateway，一条路由，后端写的是名字 `upstream.idp.test:8080` |

装规则的脚本由 `run.py` 另起临时容器来跑，接在 `netns` 的网络命名空间里。给它的参数与 `deploy/compose/compose.yml` 里的相同：只读的根文件系统，root，除 `NET_ADMIN` 外没有别的 capability。这里没有 `front`，所以回环上一个都不另外放行。

## 结果

2026-11-18，agentgateway 1.7.0，docker 29.8.1：8/8。

| 用例 | 看什么 | 结果 |
|---|---|---|
| EG-01 | 不装规则。名字改指到另一个地址，不发请求地等 20 秒，再发一个请求：它到了另一个地址，调用方得到 200 | PASS |
| EG-02 | 装上规则（`pin-egress.sh once`）：名字被钉在它这时解析到的地址上。之后重启网关，它要在规则底下重新解析这个名字：请求得到 200，收到它的是登记的那个服务器 | PASS |
| EG-03 | 装上规则之后名字改指，等 20 秒再发请求：另一个地址没有收到，调用方得到 503。重启网关（它解析到的只有另一个地址）之后也一样。规则再装一遍，没有把名字现在指的地址加进去。名字指回去之后请求照常，规则不用动 | PASS |
| EG-04 | 从网关所在的网络命名空间往外连：钉住的地址和端口连得上；同一个地址的另一个端口、另一个服务器、一个内网地址、`169.254.169.254`、回环上网关自己的管理地址、IPv6 的回环，都被规则拒绝。常驻的那个每秒重写一遍规则的 10 秒里，连另一个服务器 4669 次，每一次都被拒绝 | PASS |
| EG-05 | 配置里多了一个后端：常驻的那个几秒之内把它钉住。一个名字解析出两个地址：两个都钉住。`pin-egress.sh forget`（常驻的那个同时在跑）：三个名字都按现在的解析重新钉过 | PASS |
| EG-06 | 占着网络命名空间的容器被杀掉：常驻的那个 0.1 秒之后也停了（它与占位容器共用 PID 命名空间） | PASS |
| EG-07 | 配置里去掉一个后端：几秒之内它不再被放行，连它的地址和端口被规则拒绝（113），经网关去剩下的后端的请求照常。名字改指之后把它放回配置：放行的是它原来钉着的地址，名字现在指的地址被拒绝。配置文件拿走几遍再放回去：放行的前后不变，请求照常。这个用例在 EG-06 之前跑 | PASS |
| EG-08 | 配置文件读不了（模式 0600，脚本是 root 但没有 `CAP_DAC_OVERRIDE`），读不了的这几遍里：常驻的那个还在跑，放行的原来的三个不变，放行的地址和端口照常连得上，经网关的请求仍然得到 200，标准错误上说了读不了，这一行没有每遍都说。文件读得了、配置里多一个后端之后：几秒之内它被钉住，标准错误上说了又能跑了。这个用例在 EG-06 之前跑 | PASS |

`EG-01` 记的是被测的这个二进制的行为，不是期望它这样：换了版本它不再跟着走，这一条就不通过，那时要回头看规则还需不需要。

## 看清的事

1. **网关跟着名字走，而且没有哪项设置能让它不跟。** 配置的 `dns` 段只有 `lookupFamily` 和 `edns0` 两项；二进制里的 `dnsRebindingProtection` 管的是 MCP 的 `Host` 头，与后端的解析无关（读的是二进制里带的配置 Schema）。另外单独试过、不在用例里的：名字解析到 `127.0.0.1` 时网关去连了自己，解析到 `169.254.169.254` 和一个内网地址时它也去连，等到超时。
2. **发请求会让它接着用记着的地址。** 名字改指之后一直有请求的话，20 秒之内它没有换地址；停下来不发请求，20 秒之后的第一个请求就到了新地址。多久不发才会换没有量。
3. **放行解析器不能按 53 端口写规则。** Docker 在容器的网络命名空间里把发往 `127.0.0.11:53` 的查询改写到一个随机端口，改写在过滤之前。按 53 端口放行的规则一条都匹配不上，装上之后什么名字都解析不了。要按查询最初发往的地址来匹配（`--ctorigdst`）。Docker 的解析器自己不认识的名字，是从这个命名空间里去问上游解析器的，上游的地址写在 `resolv.conf` 的 `# ExtServers:` 那一行注释里，也要放行。
4. **规则不能先清空再重建。** 这样写的时候，12 秒里对一个没有放行的地址试了 2317 次，有 34 次连上了。现在整条链用 `iptables-restore --noflush` 一次换上。
5. **被规则拒绝和被对方拒绝要分得开。** 规则用 `icmp-admin-prohibited` 拒绝，`connect` 得到的是 `EHOSTUNREACH`（113），对方自己拒绝是 `ECONNREFUSED`（111）。用例靠这个区别判断是谁拒绝的。
6. **占着网络命名空间的容器换过之后，新的命名空间里什么规则都没有。** 还活着的、接在旧命名空间里的容器只剩一个回环。所以规则在每次启动时由跑完就退出的一步重新装，常驻的那个与占位容器共用 PID 命名空间，占位容器一死它就跟着死。这一条在池里的样子由 compose 套件的 `SH-22` 看。

## 对照

把 `pin-egress.sh` 改坏，一次一处，跑一遍整套再改回去。结果见 `run.py` 所在提交的说明；改法在这里：

| 改坏的地方 | 哪个用例发现 |
|---|---|
| 一个名字每次都重新解析 | 待填 |
| 解析器按 53 端口放行 | 待填 |
| 规则先清空再重建 | 待填 |
| 一个名字只钉一个地址 | 待填 |
| `forget` 不丢掉钉住的 | 待填 |
| 没有放行的一律接受 | 待填 |
| 不装 IPv6 的规则 | 待填 |
| `OUTPUT` 不跳到这条链 | 待填 |
| 不放行上游解析器 | 待填 |
| 配置里去掉的后端仍然放行 | 待填 |
| 常驻的那个一遍没跑成就退出 | 待填 |

## 没有覆盖的

- **第一次解析到的就是不该去的地址。** 规则钉的是名字第一次解析到的地址，它信的是那一刻的解析器。没有一份独立于解析器的"登记的地址"可以对照。
- **真实的上游。** 地址会正常变动的后端（CDN、多地域）在这套做法下要人工 `forget`，没有试过这样的后端。
- **IPv6。** 这个网络里没有 IPv6 地址。试过的只有回环 `::1` 被拒绝；后端只有 IPv6 地址时，这套规则下它连不上。网关同时拿到 A 和 AAAA 时先连哪个、IPv6 被拒绝之后会不会改连 IPv4，没有试；这里的配置写的是 `lookupFamily: V4Only`。
- **UDP 和别的协议。** 规则只放行 TCP 的后端和解析用的 53 端口，别的一律拒绝；网关用不用得到别的没有看。
- **多个网关实例、Kubernetes。** 那里对应的是 NetworkPolicy，没有做。
