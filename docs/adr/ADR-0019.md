# ADR-0019 — 回环上的管理 BFF：读审计，撤销和封禁仍走原来的客户端

> **状态**：Proposed · **版本** V1.0 · **日期** 2026-11-23  
> 本 ADR 为设计建议，不是已经执行的技术审批、生产基线或运行验收。执笔的是 AI 编码助手。  
> 这不是仓库所有者把界面冻结整个解开的决定。`portal/prototypes/` 和 UX 用例仍冻结。状态是 Proposed。

## 背景

2026-11-23 仓库所有者定：Trace、审计和 SLO 先做，然后做管理后台，分阶段解冻。第一段是只读观测，加上已有的撤销、恢复和封禁。新路由的批准和发布仍留给 Fabric。

`gateway-control` 已经能 `revoke`、`restore`、`revocations`、`ban`、`unban`。它们走 `revokerclient`，出示撤销者证书。审计文件由 `internal/platform/audit` 写成 0600 的 JSONL。回滚在 `gateway-control` 的 `main` 包里，和发布历史绑在一起。

`P1-SS-04` 仍在：agentgateway 接受两个 `Host` 头。前置 Nginx 那一跳会丢掉。本进程自己也要拒绝。

## 推荐决策

1. **新增 `gateway-console`，只听回环 IP。** `--listen` 默认 `127.0.0.1:19100`。必须是回环 IP 加端口。`0.0.0.0`、空主机、主机名（包括 `localhost`）在 `Listen` 之前拒绝，退出码 2。这一步不把它挂到 front 后面。
2. **审计只读。** `GET /v1/audit` 用 `audit.ReadRecent`。不给 `--audit-log` 是 404。文件不存在是 404，应答里不回显路径。符号链接、非常规文件、组或其他人可读，是 403，不读内容。查询参数只有 `limit`（默认 50，最大 200）、`trace_id`、`decision_id`、`outcome`。
3. **撤销和封禁不另写协议。** 五个参数 `--authz`、`--authz-name`、`--tls-cert`、`--tls-key`、`--tls-ca` 一起给或不给。给了就用 `revokerclient`，和 `gateway-control` 同一条客户端。不给时这三个路径是 404，审计读取仍可用。请求体不认识的字段拒绝，并且不去连 gateway-authz。原因不进本进程的日志。
4. **两个 `Host` 头在进入处理函数之前就是 400。** Go 的 HTTP 服务器对 HTTP/1.1 的多个 `Host` 头直接拒绝。处理函数里若仍看到多于一个 `Host`，也是 400。两种情况都不调用 gateway-authz。
5. **回滚、发布、编译新路由不做。** 那些逻辑在 `gateway-control` 的 `main` 包里。这一步不复制，也不另起子进程去调它。
6. **界面冻结保持。** `scope_freeze.ui_ux_expansion.state` 仍是 `FROZEN`。不改 `portal/prototypes/`，不加 UX 用例，也不做 React 页面。

## 为什么这样决定

撤销者是谁，已经由证书决定。再做一个用户表，会多出一套口令。BFF 只是把同一条客户端放到回环的 HTTP 上，方便下一步的页面调用。听在回环上，是因为 `P1-SS-04` 还在，也还没有决定怎样把它挂到 front 后面。

回滚要动已发布的快照。那和「新路由仍留给 Fabric」不是一件事，但实现嵌在发布器里。拆出来的代价比这一步要读的审计和要转发的撤销大。先留在 `gateway-control`。

## 被考虑的替代方案

- **把回滚搬进这个进程。** 要拆 `gateway-control` 的 `main`。这一步不拆。
- **用子进程调用 `gateway-control rollback`。** 多一个可执行文件路径，参数和退出码要再对一遍。不选。
- **解开 `portal/prototypes/` 的冻结，直接改原型。** 所有者要的是本仓库里单独的页面，而且原型冻结的条件没有全部满足。不选。
- **默认听 `0.0.0.0`。** 不选。

## 做出来了（V1.0）

`cmd/gateway-console`、`contracts/console/openapi.yaml`。写代码和验证的是 AI 编码助手。**这不是对本 ADR 的决定**，状态保持 Proposed。

### 页面（V1.1）

`console/` 是 React 和 TypeScript 页面。`npm run build` 写出 `console/dist`。`gateway-console --ui console/dist` 在同一个监听上提供这些文件，`/v1/` 仍走接口。不给 `--ui` 时没有页面。页面只调用审计、撤销和封禁三个路径。静态文件只允许 html、css、js、svg，拒绝符号链接和跑出目录的路径。

### 没有做的

- 回滚。
- 发布、编译、新路由批准。
- 把这个进程写进 `compose.yml` 或 systemd。
- 黑盒套件不启动它。源码哈希会变，是因为哈希覆盖 `cmd/` 和 `internal/` 下全部非测试 Go 文件。

## 成本与剩余风险

- 听在回环上。本机上的其他用户也能连到这个端口。撤销仍要撤销者证书；没有配证书时，改状态的路径不存在。审计文件若配了，本机上能连到这个端口的人可以读最近的记录。
- 应答里的撤销原因来自 gateway-authz 已经存下的表，和 `gateway-control revocations` 一样。本进程不把原因写进自己的日志。
- 两个 `Host` 头的拒绝依赖 Go 的 HTTP 服务器。换传输层时要再验一次。
