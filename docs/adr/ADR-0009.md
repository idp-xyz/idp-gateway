# ADR-0009 — 进入开发阶段的仓库结构与 Go 技术基线

> **状态**：Accepted · **日期** 2026-11-10 · 由 zhongsunqiao 确认后执行  
> 本 ADR 只决定代码放在哪里、用什么搭。它不改变任何验收用例或 STD-CP 门禁的 `NOT_RUN`。

## 背景

到提交 `b72902d` 为止，仓库是一份设计基线交付包加一个 PoC：G01–G06、8 篇 ADR、契约、18 页 Console 原型、HTML 镜像与全树校验和，以及在真实 agentgateway 上跑的 54 个黑盒用例。没有一行 Go 代码，PoC 里的 PDP 是 Python 写的 Mock。这个状态打了标签 `baseline-v1.0-poc`。

项目的实现语言是 Go。公司内的 Go 服务（以 idp-parcel 为代表）已经有一套成型的布局，并使用 Bento-Go（`go.idp.xyz/idp-bento-go`）。

## 决定

1. **模块名** `go.idp.xyz/idp-gateway`。Go 版本与 idp-parcel 相同（`go 1.26.0`，`toolchain go1.26.5`）。
2. **按限界上下文分包**，每个上下文内分 `domain / application / ports / adapters`，与 idp-parcel 相同。`domain` 只依赖标准库；`application` 不依赖 `adapters`；依赖方向由 `internal/architecture` 里的测试守住。
3. **请求路径和控制面是两个二进制**。
   - `cmd/gateway-authz`：agentgateway 的 HTTP ExtAuthZ 端点，每个出站请求同步经过它。不连数据库，不引入 Bento-Go，只用标准库。
   - `cmd/gateway-control`：配置发布、对账、迁移。有代码时再建。
4. **Bento-Go 只用于控制面的上下文**（`gatewayconfig`、`egresscredential`）：它们有持久化、乐观并发和需要可靠送达的事件。约束：
   - `go.mod` 里锁定精确版本；
   - 对它的导入只出现在各上下文的 `adapters` 和装配代码里；
   - 第一次引入的那个提交同时带上 `tests/bentocontract` 和一个显式的迁移命令（框架禁止启动时自动迁移）。
   现在不引入：还没有用得到它的代码。
5. **数据面不是 Go 代码**。agentgateway 是外部的 Rust 二进制，仓库里只有它的版本锁定和原生配置，放在 `deploy/agentgateway/`。
6. **进入产品二进制的逻辑只有 Go 一份**。Python 的策略参考实现 `policy_reference.py` 移植成 Go 后删除。黑盒运行器和针对契约的参考检查暂时仍是 Python，它们不进入产品。
   黑盒套件需要的观察与故障注入手段（原来写在 Mock 里）放在 `cmd/gateway-authz` 中带 `acceptance` 构建标签的文件里；默认构建不包含它们。黑盒证据因此是验收构建的证据，不是产品构建的。
7. **交付包阶段的产物退役**：HTML 镜像与离线阅读器、`CHECKSUMS.sha256`、`DELIVERY.md`、`QUALITY_REPORT.md`、`validate_baseline.py`、`build_html.py`、Console 原型与 UX 用例（范围已冻结）、交付时的离线检查输出。需要时从标签 `baseline-v1.0-poc` 取回。

## 目录

```text
go.mod
cmd/gateway-authz/            请求路径的二进制
internal/
  egressauthz/                请求路径：判定规则、ExtAuthZ 协议、凭证发放
    domain/ application/ ports/ adapters/
  platform/                   与上下文无关的技术件（工作负载 TLS 等）
  architecture/               包依赖方向的测试
contracts/                    OpenAPI 与 JSON Schema，跨团队契约的唯一来源
deploy/agentgateway/          数据面的版本锁定与原生配置
tests/
  acceptance/                 正式验收矩阵（95 条，NOT_RUN）
    blackbox/                 对着真实 agentgateway 的黑盒用例、运行器与证据
  contracts/  security/       针对契约与参考实现的离线检查（Python）
scripts/                      尚未移植的 Python 参考实现
docs/                         G01–G06、adr/、governance/、operations/、integrations/、diagrams/、upstream/
```

以后出现时再建、现在不建空目录的：`cmd/gateway-control`、`internal/gatewayconfig`、`internal/egresscredential`、`migrations/<上下文>/`、`tests/bentocontract`、`deploy/compose`、`deploy/k8s`。其中 `cmd/gateway-control` 和 `internal/gatewayconfig` 已在 2026-11-11 建出：只有单机上的发布这一步，没有持久化，所以还没有引入 Bento-Go（见 [ADR-0010](ADR-0010.md) 的"单机发布器的第一版"）。

黑盒用例放在 `tests/acceptance/blackbox/`，与正式验收矩阵分开：黑盒用例通过不等于矩阵里对应的用例离开 `NOT_RUN`。

| 原位置 | 新位置 |
|---|---|
| `decisions/` | `docs/adr/` |

## 没有定的

- **控制面的部署形态**（standalone 文件下发还是 Kubernetes）。它决定 `gateway-control` 怎么写，本 ADR 不涉及。2026-11-11 起见 [ADR-0010](ADR-0010.md)（Proposed）。
- **凭证从哪里来、撤销从哪里来**。`gateway-authz` 的第一版从文件读策略和凭证，撤销状态只在内存里，都是占位；Secret Manager 和 Provider 令牌端点还没有接。向 Gatekeeper 询问账户授权已经有了适配器（`internal/egressauthz/adapters/gatekeeper`，默认不启用），但它问的授权类型目前只存在于本机联调用的实例里，Gatekeeper 自己的模型里还没有，见 `tests/integration/gatekeeper/README.md`。
- **契约的归属要跟着改**。`contracts/gatekeeper/openapi.yaml` 里的 `/v1/extauthz/check` 现在由本仓的 `gateway-authz` 实现，而不是 Gatekeeper；ADR-0003 与 ADR-0008 里"Gatekeeper 下发凭证"的表述也要相应修订。文件位置和这两篇 ADR 的正文本次都没有动。
- **黑盒运行器是否改写成 Go**。目前保留 Python。
- **黑盒套件里的旧名字**。PDP 换成 `gateway-authz` 之后，证书名、主机名 `gatekeeper.idp.test`、端口名和用例标题里仍叫 Gatekeeper。换 PDP 的那一步刻意没有改名，好让前后两次运行只差 PDP 的实现。
- **Bento-Go 的版本**。评估时读的是 `v0.1.0-rc.2`，它仍是候选版，PostgreSQL 适配器标注为实验性，发布时只对 TMS 与 Parcel 两个消费者做合同验证。引入时再确认当时的版本。
