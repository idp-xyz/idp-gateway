# ADR-0024 — 看守另外照看叠加文件里的服务，钉住的名字换了地址时让网关跟上（gateway-control keep --tend、--tend-pinned）

> **状态**：Proposed · **版本** V1.0 · **日期** 2026-11-24  
> 本 ADR 为设计建议，不是已经执行的技术审批、生产基线或运行验收。实现和测试记在文末「做出来了（V1.0）」，不是验收通过。执笔的是 AI 编码助手。  
> 它补充 [ADR-0010](ADR-0010.md)（Accepted）第 10 条「看守」那一款；那一款的原文没有改。不给本篇的两个参数时，看守与 ADR-0010 V1.6 写的一样。正式门禁仍为 `NOT_RUN`。

## 背景

[ADR-0010](ADR-0010.md) V1.6 的看守（`gateway-control keep`）只看 `deploy/compose/compose.yml` 里常驻的三个容器：`netns`、`agentgateway`、`front`。有没在跑的，它跑 `docker compose up -d`（用它拿到的 `--compose-file`、`--compose-env-file`）。它只有一处会停容器：`front` 和网关接着的是一个已经不在了的网络命名空间时，先 `stop front agentgateway` 再 `up -d`。池里每个容器都是 `restart: "no"`，原因写在 ADR-0010「被考虑的替代方案」里。

叠加文件加进来的服务，看守看不到：

- `gateway-authz`（`gateway-authz.yml`）。网关每个请求都经 extAuthz 问它。它死了，每个请求都是 503（失败关闭），直到有人来处理。
- 签名器（`provider-signer.yml`）：占着命名空间的 `provider-signer`，进程 `signer`。
- `compose.yml` 里常驻的 `egress-watch`。
- 两个协调器（`coordinators.yml`）：`sf-token-coordinator`、`authz-state`。`authz-state` 停着时判定是 503 `REVOCATION_STATE_UNAVAILABLE`；这时重启的副本以退出码 1 退出，没有谁再起它（[tests/integration/coordinators](../../tests/integration/coordinators/README.md) 的 CO-05）。

这些死了，看守看到的仍是一个完整的池，什么都不做。

另一件事是地址。`deploy/compose/pin-egress.sh` 把每一处 `host: 名字:端口` 钉在这个名字**第一次**解析到的 IPv4 地址上。CO-07 量过：两个 `gateway-authz` 副本一起重启之后地址互换了，去新地址的请求是 503；要 `docker compose run --rm --no-deps egress forget`，**再**重启网关才好（只 `forget` 时 6 个请求里还有 3 个去了旧地址）。单独重启一个副本，两遍都没有换地址。看守两步都不做。

## 推荐决策

1. **`gateway-control keep --tend <服务>`，可以给多次。** 不给就是现在的样子：只看三个常驻的，不多跑一条 docker 命令，写的每一行 JSON、给出的指标与原来一字不差。已有的测试不改一处照样通过。

2. **`--tend-pinned <服务>`，可以给多次：** 网关经 `pin-egress.sh` 按名字连的服务（`gateway-authz`、`provider-signer`）。它包含 `--tend`。

3. **启动时核对名字。** 要是 compose 认的服务名；不能是 `netns`、`agentgateway`、`front`（本来就看），也不能是跑完就退出的 `place`、`confirm`、`egress`、`signer-egress`；同一个名字不能给两次（`--tend` 和 `--tend-pinned` 合起来算）。每个名字都要在看守拿到的 compose 文件里：用看守本来就用的 `-p`、`-f`、`--env-file` 跑一次 `docker compose ... config --services`。名字写错了，看守会把一个不存在的服务当成一直没在跑，一直去起它。不合要求：退出码 2，与看守别的命令行错误相同；除了那一条 `config --services`，什么都没做。`config --services` 自己没跑成（docker 够不着、文件里缺变量）：退出码 1。

4. **每一眼也看每个照看的服务的每一个容器**（`docker compose run` 临时起的不算；`--scale`、`deploy.replicas` 时不止一个）。有容器没在跑，或者一个容器都没有：跑看守本来就跑的那条启动命令。同样先试一下占不占得了池（一次发布占着时不动手），同样越试越稀，同样写一行、同样记进指标。`docker compose up -d` 照 `depends_on` 来（两个协调器健康了才起 `gateway-authz`），看守自己不排先后。

5. **地址。** 看守为每个钉住的服务记着它的容器在这个 compose 项目的网络上的 IPv4 地址（带这个项目标签的网络；`external` 的别的网络不算，网关在项目网络上按名字找它们）。任何一眼（不只是起过容器之后的那一眼）看到钉住的服务有了一个记着的里面没有的地址，并且照看的和常驻的容器都在跑：先 `egress forget`（`docker compose -p … -f … --env-file … run --rm --no-deps egress forget`），再走已有的那条路：`stop front agentgateway`，然后 `up -d`（`place`，`egress` 跑一遍，网关，`confirm` 对上了才开 `front`）。之后记下这一眼的地址，换掉原来记着的：`forget` 丢掉了原来所有的钉。
   - 看守启动之后看成的头一眼**只记下**。看守启动之前 `egress` 那一步钉的是哪些地址，它不知道。
   - 地址少了（缩容）什么都不做。原来的钉还在规则里，`forget` 之前一直在。
   - 一次发布正占着池：这一眼不动手，也不记下，下一眼再看。
   - `forget` 没成：不停网关（停了起来也连不上新地址），不记下，越隔越久再试。`stop` 没成：不接着起，不记下。
   - 有容器没在跑的那一眼只跑启动命令，不 `forget`；都在跑了，下一眼再看地址。
   - 这一眼看照看的服务没看成（`docker ps`、`inspect`、`network ls` 有一条没成）：这一眼当作没看成，什么都不做，三个常驻的也不动，下一眼再看。

6. **报告。** 给了这两个参数时，看守写的那一行多四项：`tended`（动手之前每个服务的容器：名字、在不在跑、状态、地址；钉住的标 `pinned`），`tended_why`（哪几个不是每个容器都在跑），`moved`（`"服务 地址"`），`tended_after`（动手之后）。`action` 多三个值：`forget+stop+start`，以及没做完的 `forget`、`forget+stop`。指标多三样：`idp_gateway_pool_tended_running{service,pinned}`、`idp_gateway_pool_unfollowed_addresses`、`idp_gateway_pool_repins_total`；`idp_gateway_pool_starts_total` 照旧数启动命令跑了几次，这几种也算在里面。日志里只有服务名、容器名、状态和 IPv4 地址，没有秘密。

7. **看守仍不重启在跑着的容器，只有两处例外：** 已有的那一处（接错了命名空间），和第 5 条的前置代理与网关。这是本篇有意放宽的一处。理由：钉住的名字有了新地址时，去那个地址的请求已经在失败（关闭），只 `forget` 修不好，在跑着的网关还连它记着的地址（CO-07）；网关要重新起来才会重新解析。重启让整个池断一下（`front` 先停，`confirm` 对上了才开），换掉的是一直有一部分请求 503。

## 为什么这样决定

看守存在的理由是池里的容器都不设重启策略：由 docker 自己起来的网关不经过 `place` 和 `confirm`。叠加文件里的服务同样是 `restart: "no"`，同样没有谁起它们。让看守照看它们，用的是它已经有的那条启动命令：`up -d` 本来就照 `depends_on` 等两个协调器健康，本来就经过 `place` 和 `confirm`，在跑的容器不动。没有新的启动路径。

默认关着，是因为一个池带不带叠加文件、带哪几个，看守自己不知道；`config --services` 里的服务也不都该照看（跑完就退出的那几步，测试里加的替身）。由操作员点名，名字由 compose 核对。

地址的那一条，不在 `pin-egress.sh` 里做：它"一个名字只解析一次"是有意的（ADR-0010 V1.8，`EG-01`：锁定的网关跟着名字走到哪里就去哪里）。看守做的是 README 里写给人做的两步，只在它看到地址确实变了、池里照看的都在跑时做。重启网关走的是已有的停、起那条路，不是 `docker compose restart agentgateway`：后者不经过 `place`（README「不经过 place 的重启」）。

## 被考虑的替代方案

- **给叠加文件里的服务设重启策略（`restart: on-failure` 之类）。** 不选。池里谁死了由谁起回来就分成了 docker 和看守两处；docker 按重启策略起容器不看 `depends_on`；地址换了的那一半它也不管。没有试过。
- **不要参数，看守照看 `config --services` 里所有常驻的服务。** 不选。改了默认行为；跑完就退出的、测试的替身都得另外排除；哪些是网关经出口规则连的，compose 文件里看不出来。
- **只 `forget`，不重启网关。** 不选。CO-07：6 个请求里还有 3 个去了旧地址。
- **`forget` 之后 `docker compose restart agentgateway`**（README 原来写的第二步）。不选。那条重启不经过 `place`；看守已有的 `stop front agentgateway` 加 `up -d` 经过 `place`、`egress`、`confirm`。
- **每一眼从网关的命名空间里读规则里钉的是哪些地址**（像套件那样 `compose run … iptables -S`），不靠自己记。好处是没有"头一眼只记下"的盲区。不选：每一眼要起一个带 `NET_ADMIN` 的容器。以后可以再议。
- **让 `pin-egress.sh watch` 跟着名字重新解析。** 不选，理由见上一节。

## 成本与剩余风险

- **让网关跟上一次地址，整个池断一下。** `front` 先停，网关等在途的请求做完再停（最多 `stop_grace_period` 60 秒），然后 `place`、`egress`、网关、`confirm`、`front`。量到的时长在文末。
- **头一眼的盲区。** 看守启动之前地址就已经变了的，它看不出来，直到再变一次。这时仍要人做 README 里那两步；重启看守不管用（它又只记下）。
- **看守启动时没在跑的钉住的容器**，起来时多半拿回原来的地址；没在跑的容器没有地址，看守记不下它，起来之后算一个新地址，会多一次网关重启。
- **扩容**多出来的副本是新地址，没有被钉住，会让网关跟上一次。这是对的：不跟上，去它的请求是 503。
- **`provider-signer`（签名器的命名空间）单独死了**，和 `netns` 是同一个问题：`up -d` 把它起起来，`signer` 还接在原来的命名空间里。看守不为它先停 `signer`。没有处理，也没有试。
- **`egress-watch`** 可以 `--tend`，没有试。
- **每一眼多三条 docker 命令**（`ps`、`inspect`、`network ls`），只在给了参数时。
- **systemd 单元没有改。** `idp-gateway-pool-keep.service` 的 `ExecStart` 仍是原来那一条；要照看叠加文件里的服务，看守和开机的单元得用同一组 compose 文件，单元文件开头的注释写了参数的样子，没有在 systemd 里跑过。
- **告警规则没有加。** 三样新指标没有写进 `idp-gateway-pool.rules.yml`，也没有进 `tests/contracts` 对着的那份指标样本（不给参数时给出来的与它一字不差）。
- **在跑着的 `gateway-authz` 自己的地址变了，它自己会一直答 503。** 开发时给一个在跑的副本换地址（`docker network disconnect` 再 `connect`），看守照样让网关跟上了，网关也把请求送到了它的新地址，但它自己对每一次判定都答 503 `REVOCATION_STATE_UNAVAILABLE`：直接问它 16 次、60 秒，次次如此。多半是它到 `authz-state` 的连接还是从旧地址开的；没有查 `gateway-authz` 的客户端代码。容器重启换的地址（CO-07 那种）是新进程，没有这个问题，所以套件改用重启（见文末）。`authz-state` 自己重启到另一个地址时 `gateway-authz` 那边会怎样，没有试。
- 没有正式 SLO，也没有数字错误预算。

## 变更与回退条件

需由仓库所有者复核和决定；在此之前保持 Proposed。执笔的是 AI 编码助手，这不是决定。

回退：不给 `--tend`、`--tend-pinned`。那时看守不跑 `config --services`，不看别的服务，不 `forget`，写的行和指标与原来一字不差。若不接受第 7 条的放宽，可以只保留 `--tend`、去掉 `--tend-pinned`，地址换了仍由人做那两步。

## 做出来了（V1.0）

2026-11-24。写代码、验证和执笔的是 AI 编码助手。状态仍是 Proposed。这一节只记工作区里现在的代码（在 `72afa82` 之上，还没有提交）和当天跑过的测试。不是技术审批，不是生产基线，也不是验收通过。没有跑黑盒套件。正式门禁仍是 `NOT_RUN`。没有改 `contracts/` 和 `go.mod`（仍然没有 `require`），没有碰生产的 Gatekeeper。

做了这些：

- `internal/gatewayconfig/domain/tended.go`：`Service`、`Replica`、`Down`。只有规则，不碰 `net`。
- `ports.Others`：`Services(ctx, names)`、`Forget(ctx)`。`ports.Pool` 没有改，原来的假实现不用动。
- `application.Keeper.Tend(others, services, pinned)`；`Tending` 多了 `Services`、`Moved`、`Forgot`、`ServicesAfter`。不调 `Tend` 时 `Run` 和 `tend` 走的是原来的每一步：用不着动手的判断从"三个都在跑"换成"三个、照看的都在跑，地址没多出来"，不照看时两者相同。
- `container.Pool`：`Services`（`docker ps`，一次 `docker inspect`，`docker network ls --filter label=com.docker.compose.project=…`，只算项目网络上的 IPv4）、`Forget`（`docker compose -p … --env-file … -f … run --rm --no-deps egress forget`）、`Declared`（`… config --services`）、`CheckTended`。
- `telemetry.Metrics.Tend`：三样新指标，只在设了时给出。
- `cmd/gateway-control`：`--tend`、`--tend-pinned`，启动时核对，那一行的四项新内容。

和推荐决策不完全一样、或者推荐里没说的几处，都写进了上面各条：

- `forget` 没成的那一眼不算"动过网关"。原来的看守在"动过手却没对成账"之后，账一对上就提前再试；照搬的话，`forget` 每次失败之后下一次对账都会把等待清零，越试越稀就没有了。单元测试里量到的是：照搬时 `forget` 在第 5、15、35、65、125 秒，改了之后是 5、15、35、75、155 秒。
- 照看的服务这一眼没看成，整眼算没看成（第 5 条最后一款）。推荐里没有说。
- 起过容器的那一眼不看起来之后的地址，下一眼再看（第 5 条倒数第二款）。
- 套件的 KP-03 没有用推荐里举的 `docker network disconnect` 加 `connect`，原因见"成本与剩余风险"倒数第二条；用的是重启到另一个地址，见下。
