## 背景

出站网关验调用方令牌，用的是锁定的 agentgateway 1.7.0。提交 `e94602e` 写明：按地址取 JWKS（`jwks.url`）时，不认识的 `kid` 不会立刻重取；本机 Hydra 的 `Cache-Control` 下要等大约 16 分钟才刷新。测量的细节在[联调报告](../../tests/integration/gatekeeper/README.md)第 4 点（2026-11-11，假的身份提供者；报告里写这些时间仍然成立）：

- 令牌的 `kid` 不在已有密钥集里时，不会立刻重取。上游为此开的议题和修复没有进 1.7.0。
- 重取间隔跟着响应的 `Cache-Control`。本机 Hydra 的头是 `private, no-cache, no-store, must-revalidate`。这种头、以及没有这个头，都是启动后第 982 秒（16 分 22 秒）才再读。`max-age=60` 时大约 63 到 66 秒。
- 身份提供者答 503 并带一段 JSON 错误体时，1.7.0 把这段正文当成新的密钥文档去加载，解析失败（`missing field keys`），然后不重试。那次试验在之后的 207 秒里没有再读，其中后 100 秒身份提供者已经恢复。已有的密钥继续被信任。配置里没有能设「最多再信任多久」的项。
- 在 `jwks` 下面写 `maxAge` 时，`--validate-only` 说配置有效，字段不起作用。同样的未知字段写在上一层 `jwtAuth` 下面会被拒绝。

`jwks.file` 不一样。2026-11-20 在锁定的 1.7.0 上、写代码之前量过：原子替换这个文件之后，网关自己重新加载密钥，大约 0.3 到 0.4 秒，不用重启，也不用重载配置。加一把 `kid` 和去掉一把都是这样。`deploy/compose` 已经用文件（`tls/jwks.json`），当时没有把文件同步起来的程序。

2026-11-11 的 `GK-12`（`--key-rotation`）走的是 `jwks.url`。用例期望 60 秒内接受新密钥，没有通过。

## 推荐决策

1. **网关只读本机文件。** 不把 `jwks.url` 当作跟上换钥的办法。同步由控制面的一条命令做，不在请求路径上。
2. **新的限界上下文 `internal/jwkssync`。** 只用标准库。分包照 [ADR-0009](ADR-0009.md) 第 2 条：`domain`、`ports`、`application`、`adapters`（`httpfetch`、`filestore`、`metrics`）。
3. **命令是 `gateway-control sync-jwks`。** 参数有 `--url`、`--output`、`--once`、`--interval`、`--timeout`、`--max-stale`、`--empty-on-stale`、`--mode`、`--plain-http-host`、`--tls-ca`、`--tls-cert`、`--tls-key`、`--metrics-listen`。已有的发布、撤销、历史命令不改。
4. **先校验，再落盘。** 合格的一份是恰好一个 JSON 对象。`keys` 非空。每把密钥有非空字符串 `kty` 和 `kid`。`kid` 不重复。私钥参数 `d`、`p`、`q`、`dp`、`dq`、`qi`、`oth`、`k` 出现，整份拒绝。摘要按 `kid` 排序后的规范形式计算。身份提供者把同一套密钥换个顺序，不引起重写。
5. **取的地址收紧。** 只接受 `https`。明文 `http` 只许回环地址的字面量（`localhost` 不算，它要靠解析），或者与 `--plain-http-host` 相同的那一个裸主机名。不走代理。不跟随重定向。不是 200 的应答拒绝，正文不解析，不写进文件。
6. **原子写。** 临时文件，`chmod`（0600 或 0644），刷盘，改名，刷目录。写不成时原来的文件不动。
7. **陈旧有上限。** 结局是 `UPDATED`、`UNCHANGED`、`FETCH_FAILED`、`STALE_EXPIRED`。超过 `--max-stale` 仍取不到：不给 `--empty-on-stale` 时文件保持上一份；给了就把文件写成 `{"keys":[]}`，验证失败关闭。空集不是一份合格的密钥集。它只用于这一条失败关闭。
8. **指标。** 给了 `--metrics-listen` 时，在 `/metrics` 上按 Prometheus 的文本格式给出。

## 为什么这样决定

1.7.0 按 URL 取时，既跟不上换钥，也没有有界的陈旧期。文件被替换后它自己会重载。这一条在锁定的二进制上量过。同步放在 `gateway-control` 里，请求路径不加进程，`go.mod` 不加依赖。校验挡住私钥和 503 的错误体，避免把不该信任的字节写成网关要去用的文件。

## 被考虑的替代方案

- **继续用 `jwks.url`，等上游遇到未知 `kid` 就重取。** 议题和修复都没有进 1.7.0，没有时间表。不选。
- **让 Hydra 的响应带 `max-age=60`。** 联调报告里量到大约 63 到 66 秒，仍略长于 `GK-12` 期望的 60 秒。重取那一刻身份提供者答 5xx 时会更长，而且 503 的错误体有上面那条不重试的行为。不选作这一步的做法。
- **在 `jwks` 下面写 `maxAge`。** 1.7.0 不认这个字段。不选。

### 没有做的

- 换镜像（升级），和发布器证书的签发、轮换。那是开发计划 4.4 的另外两样。这一篇不做。
- 没有 systemd 单元。联调套件自己起这个进程。V1.0 这一版没有把 `sync-jwks` 写进 [deploy/compose/compose.yml](../../deploy/compose/compose.yml)。

## 成本与剩余风险

- 多一个要跑、要看的进程。它不在请求路径上。它停了，文件不再更新，网关不报错，继续用文件里的密钥。旧公钥能再用多久，由 `--max-stale` 和有没有 `--empty-on-stale` 决定。没人看着这个进程时，陈旧期不起作用。
- `--empty-on-stale` 把文件写成空集之后，用这套密钥的令牌都会失败，直到下一次取到合格的密钥集。这是失败关闭。
- 回环明文和 `--plain-http-host` 是收窄的例外。指错主机名会拒绝。指对了，那段是明文。
- 1.7.0 按 URL 取时的 503 行为，和没有 `maxAge`，这一篇不改网关二进制。绕开的办法是改读文件。
