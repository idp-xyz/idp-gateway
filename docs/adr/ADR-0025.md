# ADR-0025 — Kubernetes 出站池（egress）：清单、NetworkPolicy 与多副本协调器

> **状态**：Proposed · **版本** V1.0 · **日期** 2026-11-24  
> 本 ADR 为设计建议，不是已经执行的技术审批、生产基线或运行验收。实现和套件记在文末「做出来了（V1.0）」，不是验收通过。执笔的是 AI 编码助手。  
> 它把 [ADR-0010](ADR-0010.md)（Accepted）第 3、6、7 条写的 Kubernetes 做法，接到 [ADR-0002](ADR-0002.md)（Accepted）的出站池上，并带上 [ADR-0021](ADR-0021.md)、[ADR-0022](ADR-0022.md)、[ADR-0023](ADR-0023.md)（均为 Proposed）已经有的协调器。这是开工的范围，不是对本篇的决定；状态保持 Proposed。正式门禁仍为 `NOT_RUN`。

## 背景

[ADR-0010](ADR-0010.md) 第 10 条把运行平台分成两期：先单机 docker compose，以后再上 Kubernetes。单机池在 `deploy/compose`，机制验证在 `tests/integration/compose`、`coordinators`、`sfintl`。Kubernetes 上只验过「不可变快照 + 滚动替换」这一块（`tests/integration/kubernetes`），没有 JWT、ExtAuthZ、承运商、协调器，也没有 NetworkPolicy。

[ADR-0002](ADR-0002.md) 按安全域分池。Ingress 和 AI 池没有做。单机上的出口钉在 `pin-egress.sh`；Kubernetes 上同语义的出口控制应是 NetworkPolicy。

[ADR-0022](ADR-0022.md) 与 [ADR-0023](ADR-0023.md) 的协调器在 compose 叠加文件里已经能带两个 `gateway-authz` 副本跑。Kubernetes 上需要：协调器单写者、状态落在 PVC、authz 多副本、证书进 Secret、镜像按摘要。

## 推荐决策

1. **先做出站（Egress）池。** Ingress 池和 AI 池是以后的一步，本篇不排期。

2. **清单是纯 YAML + kustomize**（`kubectl apply -k`，kubectl 自带）。不用 Helm，不用 Operator，不加 CRD。布局是 `deploy/kubernetes/egress/base/` 和测试叠加 `deploy/kubernetes/egress/overlays/kind/`。一个池一个命名空间，出站池是 `idp-egress`。

3. **本仓库的进程做成最小镜像：** `deploy/kubernetes/images/` 下 `FROM scratch`，COPY 主机上静态编好的二进制（`CGO_ENABLED=0 go build -trimpath`），`USER` 是非 root 数字 uid，没有 shell。套件本地构建，再 `kind load docker-image`；标签按二进制内容摘要。镜像仓库、签名、SBOM 放在 CI，以后再说。上游 agentgateway 镜像仍用 `deploy/agentgateway/agentgateway.lock.json` 锁住的摘要。任何带 shell 的辅助镜像（例如 initContainer）必须是本仓库已经在用、且按摘要引用的那一个（前置 nginx：`public.ecr.aws/nginx/nginx-unprivileged:stable-alpine@sha256:c3fc8fa482be50ef709c6438eb1bc98d50dbfe5a9b48be90711b8814f4dfd701`）。

4. **`idp-egress` 里的工作负载：**
   - **gateway** Deployment：同一 Pod 里 front + agentgateway（与现有 kind 套件相同），副本 2；快照是不可变 ConfigMap；滚动 `maxSurge: 1` / `maxUnavailable: 0`。
   - **gateway-authz** Deployment：副本 2，ClusterIP Service；mTLS；带 `--sf-openapi-lease-*` 与 `--authz-state-*`；`--revocations` 在 emptyDir 里，由 initContainer 仅在文件缺失时写出空表（与 `coordinators.yml` 同一理由；authz-state 的快照在监听之前会盖掉它）；`--revoker-identity`；`--rate-limits`。
   - **provider-signer** Deployment：副本 2 + Service。
   - **sf-token-coordinator** 与 **authz-state**：各 Deployment 副本 1，策略 `Recreate`（从不两个写者），状态在 PVC 上（kind 的 `standard` local-path StorageClass）；`tcpSocket` 就绪探测；各有 Service。
   - **全部 Pod 安全：** `runAsNonRoot`、`readOnlyRootFilesystem`、`allowPrivilegeEscalation: false`、`capabilities.drop: [ALL]`、`seccompProfile: RuntimeDefault`。命名空间若能接纳这些 Pod，则贴上 Pod Security `restricted` 标签（以实测为准）。
   - **证书与私钥在 Secret 里**（套件每次运行现做；生产签发以后再说，例如 cert-manager）。[ADR-0021](ADR-0021.md)：Secret 卷经 kubelet 符号链接互换更新文件；若便宜则量 gateway-authz 是否不重启就能跟上轮换，否则记为未展示。

5. **出口控制是 NetworkPolicy，不是 pin-egress.sh。** 命名空间默认拒绝入站和出站；放行 DNS；gateway → gateway-authz:9443 与 provider-signer:9444；gateway-authz → 两个协调器与承运商令牌端点；signer → 仅承运商；协调器除 DNS 外不出；各服务入站只来自它的调用方；front 端口来自测试客户端。生产上外部承运商要用 `ipBlock` CIDR（原版 NetworkPolicy 没有 FQDN 规则），并有刷新手续——以后再说。**先量 kind 默认 CNI 是否真的执行 NetworkPolicy**（一条 deny-all 必须挡住此前能通的连接）。若不执行：如实记录，清单仍保留策略，策略用例标为未展示，其余继续。

6. **Gatekeeper PDP：** base 保留可配置的 `--gatekeeper-*`；kind 叠加拿掉它们，因为集群里没有 Gatekeeper。kind 上不练这一跳。

7. **JWKS：** ConfigMap 挂成目录（网关 `jwks.file`），由套件用每次运行的密钥写入。`gateway-control sync-jwks` 做成 sidecar / CronJob 是以后的事。

8. **Kubernetes 上的发布器（gateway-control / gateway-fabric 对 API server）本篇不做**；套件与现有 kind 套件一样用 `kubectl apply` 发布。

## 为什么这样决定

出站池已经有 compose、替身承运商和两个协调器的机制证据；Kubernetes 上缺的是同一拓扑的 Deployment、PVC、Secret 和 NetworkPolicy。先做 egress，符合 ADR-0002 的分期。

kustomize 够用，且 kubectl 自带，不必引入 Helm 或 CRD。`FROM scratch` 与 compose 里「镜像只当壳、二进制挂进去」是同一意图，只是集群不能挂主机路径，所以改成把二进制打进镜像。

协调器仍是单副本 Recreate + PVC：多写者会破坏「先落盘再发布」和租约 fence；配额本就只在内存里。NetworkPolicy 替代命名空间里的 iptables 钉住，语义是「谁可以连谁」，不是「第一次解析到的地址」。

## 被考虑的替代方案

- **Helm chart / Operator。** 不选。本仓库没有 Helm；Operator 和 CRD 增加控制面与升级面。
- **协调器多副本。** 不选。见 ADR-0022 / ADR-0023；本篇只把单写者搬到 PVC。
- **继续用 pin-egress.sh。** 不选。它依赖 `NET_ADMIN` 和同一网络命名空间；Kubernetes 上同语义是 NetworkPolicy。
- **kind 上仍挂 Gatekeeper。** 不选。生产 PDP 是外部的；套件不碰 `gk.idp.xyz`，也不把本机 Gatekeeper 栈拖进这个集群。

## 成本与剩余风险

- kind 的 CNI 若不执行 NetworkPolicy，策略用例只能记「未展示」；生产 CNI 必须另验。
- 外部承运商没有 FQDN 规则，只能 CIDR；地址变动要有刷新手续。
- 证书由套件现做；生产签发与轮换未定。Secret 卷热重载是否够用，以套件是否量到为准。
- 发布器不在 API server 上；滚动发布的对账与回滚路径仍靠人手 `kubectl`。
- Ingress / AI 池、镜像仓库与签名、JWKS sidecar、正式 SLO 都不在本篇。

## 变更与回退条件

需由仓库所有者复核和决定；在此之前保持 Proposed。执笔的是 AI 编码助手，这不是决定。

不接受 Kubernetes 出站池时，撤回本篇与 `deploy/kubernetes/egress`；单机 compose 池不受影响。若要把 NetworkPolicy 换成服务网格或 DNS 级出口控制，另写一篇。

### 套件结果（2026-11-24 实测）

见 [tests/integration/k8spools/README.md](../../tests/integration/k8spools/README.md)。默认路径连跑两遍退出码 0（各 48/48）；`--control no-netpol` 与 `--control no-coordinators` 各一次退出码 0。kind 默认 CNI **执行** NetworkPolicy（deny-all 挡住此前能通的 Pod IP 连接）。KP8-06 删 authz 期间各约 7s、hard_failures=1；KP8-08 滚动发布各约 10s、hard_failures=0。离线契约 `tests/contracts/test_k8s_egress_overlay.py` 与 `tests/contracts`、`tests/security` 单元测试当日通过。没有改 Go 产品代码。

偏差（有测量理由）：gateway-authz 的凭证 Secret 经 kubelet+fsGroup 会变成组可读，产品拒绝 0644，故用 initContainer 拷到 emptyDir 并 `chmod 600`，且 `fsGroupChangePolicy: OnRootMismatch`。撤销走客户端 Pod 里的 `gateway-control`（Python 3.13 因套件 CA 缺 AKI 校验证书失败）。命名空间 PSA `enforce` 保持 privileged，只贴 warn/audit=restricted（探针与辅助 Pod 需要）。Secret 轮换热重载未量。生产证书签发、镜像仓库/签名、JWKS sidecar、Ingress/AI 池、发布器对 API server、承运商 ipBlock 刷新手续：以后再说。
