# ADR-0022 — 顺丰国际跨实例访问令牌租约协调器（sf-token-coordinator）

## 背景

[ADR-0014](ADR-0014.md) 把顺丰国际的访问令牌放在 `gateway-authz`。承运商写明：有效约 2 小时；取了新令牌，旧令牌即失效；建议过期前 5 到 10 分钟换。同一套密钥若有几个系统，要么各申请一套，要么自己同步同一枚令牌。

实现时记下的限制没有在那一步解决：多个 `gateway-authz` 副本各取各的，会互相作废线上令牌；进程重启再取一次，也会踢掉还在路上的那一枚。沙箱令牌是固定的，这一条在沙箱上验不了。替身则是每次取票都让上一枚作废。

[ADR-0020](ADR-0020.md) 把跨实例协调留到阶段 2，和 Kubernetes 多副本、PostgreSQL / Outbox 放在一起。阶段 0 决策 0-3 改为现在就做一个只用标准库的协调进程，存储先用本机文件。`go.mod` 仍然没有 `require`。

## 推荐决策

1. **新进程 `cmd/sf-token-coordinator`，新上下文 `internal/sflease`。** 四层是 `domain`、`ports`、`application`、`adapters`。`domain` 只有规则：租约键必须是 64 位小写十六进制，持有者是 1 到 128 位可见 ASCII，令牌是可见 ASCII、无分号、最长 4096 字节，以及 `Usable(now, refreshLead)`（剩下的寿命必须严格多于提前量）。它不做 I/O，不导入 `net`、`os`、`log/slog`。`ports.Store` 只有 `Load` 和 `Save`。协调逻辑在 `application.Coordinator`。文件和 HTTP 在 `adapters`。`internal/architecture` 的请求路径清单加上 `internal/sflease` 和 `cmd/sf-token-coordinator`：只用标准库，不导入 `database/sql`。

2. **协调器不持有 `app_secret` 和 `encoding_aes_key`。** 副本交给它的键是指纹：句柄、令牌端点、`app_key`、`key_version`、应用密钥的 SHA-256，各自带长度前缀后再取 SHA-256，写成 64 位小写十六进制。AES 密钥不参与取令牌，不进这个输入。协调器落盘的只有访问令牌、过期时间和寿命。文件 0600，拒绝符号链接和 group/other 可读。错误和日志不写令牌原文。

3. **一把指纹键同一时刻只有一个持有者去承运商取票。** `Acquire` 看到还能用的租约就回答 `VALID`，零次承运商调用。没有锁或锁已过期，就发单调递增的 `fence_token`，回答 `FETCH`。别人正拿着未过期的锁，调用方在 `wait`（最多 500 毫秒）内等；`Commit` 或 `Release` 关掉这一把键上的广播 channel，等待者在毫秒级被唤醒后再看一眼。锁的默认寿命 2 秒，允许 200 毫秒到 10 秒。`Commit` 必须对上持有者和 fence；过期或对不上是 409。先 `Store.Save`，成功才写入内存并放开锁。落盘失败不改内存租约，但仍放开锁并唤醒，免得所有人干等到锁超时。

4. **`gateway-authz` 不传 `--sf-openapi-lease-*` 时，行为与现在一字不差。** 五个参数要么全给、要么全不给，并且必须和 `--sf-openapi-apps` 一起给：`--sf-openapi-lease-url`（必须是没有用户信息、查询串和片段的 `https`）、证书、私钥、CA、校验证书用的名字。客户端用 `workloadtls.ClientConfigWithLogger`，证书和 CA 热重载。本地 `slots` 仍是快路径：有效期内零 RPC。进入提前换新窗口后，单进程内仍是单飞；单飞里先问协调器。`VALID` 只更新本地缓存。`FETCH` 才向承运商取一次，`Commit` 成功才放进缓存。取票失败则 `Release`，把原来的承运商错误交回去。`Commit` 失败也 `Release`，并且清空本地槽位，不留下没人协调的那一枚。

5. **协调器不可用时严格失败关闭，绝不退回单独向承运商取票。** 连不上、超时、401、5xx、答错，都是 `sf openapi token for <handle> not obtained: lease_unavailable`，日志 `result="lease_unavailable"` 并带一个固定的 `cause`。错误和日志里没有令牌、查询串和密钥。退回去各取各的，正是 ADR-0014 要消掉的互相作废。

6. **一个机制同时盖住重启和多副本。** 重启后的新进程本地缓存是空的，向协调器 `Acquire`；租约还在文件里并且还没用到提前量，就拿回同一枚令牌，承运商调用次数是 0。多个副本用不同的 `holder_id`（空则启动时用 16 字节随机十六进制），TLS 身份都是同一个 `--authz-identity`。先到的拿到 `FETCH`，其余在 `Commit` 之后被唤醒，拿到同一枚 `VALID`。`key_version` 变了，指纹就变，旧键不会串用。

7. **HTTP 只认那一个工作负载身份。** `POST /v1/sf-leases/acquire`、`/commit`、`/release`。`GET /healthz` 与 `gateway-authz` 一样，握手之后答 `{"ok":true}`，不看 URI。重复的 `Host` 头是 400，不读正文。身份为空或不等于 `--authz-identity` 是 401，不读正文、不改状态。其它方法 405，`Allow: POST`。`DisallowUnknownFields`，正文上限 64 KiB，不允许尾随 JSON。`ErrStaleFence` 是 409，参数不合格是 400 或 422，存储故障是 503。监听用 `workloadtls.ServerConfigWithLogger`，证书和 CA 热重载。

## 为什么这样决定

承运商的规则是「新令牌作废旧令牌」。多副本和重启要共享的是取票权，不是 `app_secret`。密钥仍只在 `gateway-authz` 的应用文件里。协调器拿到的是指纹和已经取到的访问令牌。泄露协调器的磁盘，看不到应用密钥和 AES 密钥；看不到指纹的原像。

失败关闭比「协调器挂了就自己取」更安全。自己取会作废别的副本已经交出去、还在路上的那一枚，故障从一个进程扩成整组凭证失效。调用方这次被拒绝，和 ADR-0014 里「取不到就拒绝、不用旧的顶上」是同一条。

文件加内存锁同时解决两件事，是因为两件事的原因相同：没有一个地方记得「当前这一枚还有效」。重启是把这个地方放在进程外面。多副本是让所有进程问同一个地方。换存储时，`Acquire` / `Commit` / `Release` 和失败关闭不用改，只换 `ports.Store`。

`domain` 的 `Secret` 不实现 `LogValue`：那一层不能导入 `log/slog`。值在未导出字段里；`String`、`GoString`、`Format`、`MarshalText`、`MarshalJSON` 都是 `[REDACTED]`。slog 的 JSON 走 `MarshalJSON`，文本走 `MarshalText`。

## 被考虑的替代方案

- **协调器不可用时退回直连承运商。** 不选。那就是多副本互相作废的原问题，只是改成在故障时发生。文末的对照 A 把这条路临时接上，失败关闭的测试因替身收到取票请求而失败，然后还原。
- **把 `app_secret` 交给协调器，由它统一取票。** 不选。等于第二处存放应用密钥。指纹足够把同一套密钥收成一把锁。
- **用共享缓存或 PostgreSQL 作为第一版存储。** 不选。阶段 0 仍要求 `go.mod` 没有第三方依赖。端口先留成 `Store`，以后可以换。
- **每个副本一个 SPIFFE ID，靠身份区分持有者。** 不选。同一工作负载的副本通常是同一个 URI。持有者 ID 在进程内生成，锁和 fence 再防旧的提交。
- **放行错误身份，只靠网络策略。** 不选。对照 B 临时拿掉身份检查，401 测试变成 400（读了正文），然后还原。

## 成本与剩余风险

- 协调器是单点。它停着的时候，本地缓存还在提前量之外的请求仍能过；一进提前换新或重启，全部失败关闭，不会自己去取。多个协调器副本不在这一版。文件锁只在这一台机器上。
- 以后换成共享存储或 PostgreSQL 时，语义应保持：先落盘再对外发布，fence 对不上就 409，存储失败不更新已发布的租约。那一次若引入 `idp-bento-go`，按 [ADR-0009](ADR-0009.md) 第 4 条同时带契约测试。
- 没有正式 SLO，也没有数字错误预算。这和 ADR-0018 接受之后仍未批准的那两项是同一件事。
- 取票成功但 `Commit` 没写上时，承运商已经作废了上一枚，而这一枚没有共享出去。这次请求失败关闭；锁被放开，下一个持有者会再取一次。这是承运商规则下不可避免的窗口，不是退回各取各的。
- 协调器磁盘上有访问令牌。权限是 0600。日志和错误没有原文。能读这个文件的人能用这枚令牌，直到它过期或被下一枚作废。
- `gateway-authz` 到协调器、协调器所在机器的出口规则，这一版没有做。
- 不传 `--sf-openapi-lease-*` 时产品路径与改之前相同，单测覆盖了原有的顺丰取票用例；黑盒重跑记在文末，套件本身不传租约参数。
