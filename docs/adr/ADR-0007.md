# ADR-0007 — 零信任策略与失败默认拒绝

> **状态**：Accepted · **版本** V1.0 · **日期** 2026-11-10（2026-11-21 仓库所有者定为 Accepted）  
> 本 ADR 为设计建议，不是已经执行的技术审批、生产基线或运行验收。

2026-11-21，仓库所有者把本篇定为 Accepted。变更条件里「验证未完成前保持 Proposed」到此为止。下面写的是这篇现在覆盖什么、不覆盖什么。

## 现在

已经如此：没有有效令牌的调用方被拒绝；问不到 PDP 时调用方得到拒绝（503），不是放行；策略拒绝仍是 403；非幂等路由没有默认重试。没有选定缓存 TTL，决策缓存没有启用。缓存策略仍由仓库所有者决定，本篇里那一句照旧。

## 背景

IDP 在取消独立 BIP 规划后，需要为 CargoPai、Parcel、Brant、Prism 和 TELOS 建立清晰的 API 安全与协议路由边界，避免供应商认证信息散落在业务代码、单一网关池形成集中故障或 Fabric 越界成为运行数据面。

## 推荐决策

JWT 验证与 Request-level/Backend-level ExtAuthZ 以明确 Policy 运行；高风险凭证调用失败拒绝；非幂等业务请求代理层无默认重试。

## 为什么这样决定

避免越权和跨租户 Token 滥用以及重复创建面单/报关。

## 被考虑的替代方案

授权依赖故障时 fail-open / Gateway 自动重试所有 POST。

## 成本与剩余风险

影响可用性，需要缓存可用性预算和业务层恢复设计，缓存策略由仓库所有者决定。

## 变更与回退条件

需由仓库所有者复核和决定；在相关 PoC、负向测试、容量与灾备验证未完成前保持 Proposed。若试验证明性能、安全、可运维性无法满足受批准目标，重新评估而非自动维持选型。
