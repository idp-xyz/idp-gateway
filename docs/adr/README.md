# 架构决策记录（ADR）

> 每项决策的状态写在各篇正文开头。截至 2026-11-18，ADR-0001 至 0008 和 ADR-0010 至 0012 是 **Proposed（待具名批准）**：它们是设计建议，不是已经执行的技术审批、生产基线或运行验收。ADR-0009 是 Accepted，它只决定仓库结构。

| 编号 | 决策 |
|---|---|
| [ADR-0001](ADR-0001.md) | agentgateway 作为首选数据面实现 |
| [ADR-0002](ADR-0002.md) | Ingress / Egress / AI 分离部署 |
| [ADR-0003](ADR-0003.md) | Gatekeeper 为 IAM 与外部凭证权威 |
| [ADR-0004](ADR-0004.md) | 外部 API 默认经过统一 L7 Egress |

ADR-0001 至 0007 随原始设计基线交付。ADR-0008 是其后依据 [P1 PoC 报告](../../tests/acceptance/blackbox/README.md) 的实测结果提出的。ADR-0010 回答 ADR-0009 留下的部署形态问题，依据同一份报告里的配置回读用例和 [kind 集群上的发布验证](../../tests/integration/kubernetes/README.md)；它在 2026-11-11 做过一次技术复核并据此修订为 V1.1，那次复核不是具名批准。同日的 V1.2 记入了仓库所有者对运行平台的决定（先单机 docker compose，以后再上 Kubernetes）和[单机上的发布验证](../../tests/integration/compose/README.md)；这也不是具名批准。V1.3 记入写单机发布器（`cmd/gateway-control`）时看清的一条规则：快照里不能有对环境变量的引用；同样不是具名批准。2026-11-12 的 V1.4 记入发布器新增的对账和带重启的发布；同日的 V1.5 记入[单机的部署文件](../../deploy/compose/README.md)和它规定的启动先后（网关启动之前先把确认过的那一份配置放到位，回读对上了才收请求）；同日的 V1.6 记入看守（`gateway-control keep`）：池里的容器死了由它跑启动命令起回来，平时由它定时对账；2026-11-17 的 V1.7 记入告警：看守每看完一眼给出指标，由一份 Prometheus 规则决定什么时候该叫人。这四次同样不是具名批准。同日的 ADR-0011 提议出站凭证正文由 gateway-authz 持有、按账户现取；这也是提案，ADR-0003 与 ADR-0008 的正文没有改。仓库所有者在 2026-11-18 同意照它动手，那是开工的许可，不是具名批准。同日的 V1.1 记入它的第一步（固定令牌加每个请求一个随机数）的实现和对着替身的验证；承运商的沙箱没有被调用。同日的 ADR-0012 提议撤销状态存在哪里、谁能改，回答 ADR-0009 留下的另一半；仓库所有者当天同意照它动手，同样是开工的许可，不是具名批准。
