# ADR-0016 — RouteIntent 预检与出站配置编译器（gateway-control compile）

> **状态**：Accepted · **版本** V1.0 · **日期** 2026-11-20（2026-11-21 仓库所有者定为 Accepted）  
> 本 ADR 为设计建议，不是已经执行的技术审批、生产基线或运行验收。它补记[开发计划](../development-plan.md) 4.3（`GW-GAP-06`，`GW-FR-039`，`GW-FR-048`）已经写进仓库的做法。执笔的是 AI 编码助手。  
> 2026-11-19，仓库所有者把这一项推后：当时手写加评审够用，出现第三四家承运商或者开始接 Fabric 时再出提案。2026-11-20，仓库所有者说「我没有第三家了，其他的全都做」。这是开工的许可，不是决定。没有第三家承运商。本篇在代码之后写成。状态保持 Proposed。

> 2026-11-21，仓库所有者把本篇定为 Accepted。此前各节里「这不是对本 ADR 的决定，状态保持 Proposed」是当时的记录，不改。

## 背景

RouteIntent 的预检当时只有 [scripts/preflight_intents.py](../../scripts/preflight_intents.py)。万邦和顺丰的 `agentgateway.yaml`、`policy.example.json` 是手写的，没有编译器。

## 推荐决策

1. **限界上下文 `internal/routecompile`。** 只用标准库。`domain` 不做 I/O，不跑网关二进制，不读文件。
2. **预检移植成 Go。** 覆盖 INGRESS、EGRESS、AI 三条，与脚本对齐：模式、规范路径、承运商登记表的允许名单、保留的主机和后缀、拒绝 IP 字面量、SNI 相符、重定向必须是 `DENY`、TLS 校验、`gatekeeper:` 绑定、拒绝敏感键、精确路径冲突、前缀重叠。对照文件是 [invalid-route-intents.json](../../tests/contracts/invalid-route-intents.json)，以及 `contracts/gateway/route-intent.example.json`、`route-intent.ingress.example.json`、`route-intent.ai.example.json`。
3. **编译只做出站。** 输入是一份编译规格。规格里没有密钥，也不许环境变量引用。输出两样，都是确定的，只用标准库：锁定的 agentgateway 1.7.0 能用的 YAML，和 `gateway-authz` 的登记表 JSON。
4. **安全缓解写在编译里，不靠手写时记得住。** 提交 `e78d62e` 的说明列出这些：只读存储（`readOnly`）、回环上的 `bindAddress`、不设会话密钥、没有环境变量引用、`networkAuthorization`、评审过的请求头白名单、按名字精确删除的头、失败关闭的后端授权前缀、不重试，以及回读路由。可选的 `frontend_limits`（`maxConcurrentRequests`、`maxConnections`）和按路由的 `localRateLimit`。不写就不出现在配置里。
5. **两条例外只在编译规格里显式打开，而且很窄。** 明文沙箱主机：环境是 `PROD` 时拒绝。池内签名器（`internal_backend_host`）：`upstream_tls` 仍必须是 `VERIFY_REQUIRED`，并且规格里写了 `backend_tls`。两条不能同时设。预检默认不带这些例外，与脚本一样严。
6. **先用锁定的二进制校验，再写文件。** 适配器在临时目录里跑 `agentgateway --validate-only`。给了 `--lock-file` 就对照 [agentgateway.lock.json](../../deploy/agentgateway/agentgateway.lock.json) 核对二进制的 SHA-256。校验不通过，输出文件不写。
7. **命令是 `gateway-control compile`。** `--spec` 做编译。`--preflight-only` 只做预检。`sync-jwks` 和已有命令不改。
8. **手写文件仍是黄金基线。** [wanbexpress/compile-spec.json](../../deploy/providers/wanbexpress/compile-spec.json) 和 [sfintl/compile-spec.json](../../deploy/providers/sfintl/compile-spec.json) 各 4 条路由。顺丰的规格含 `sfintl-labels-print`。已有的 `agentgateway.yaml` 和 `policy.example.json` 不改。

## 为什么这样决定

手写的两份配置已经对着替身和沙箱跑过。编译器要先证明自己编出来的和这两份相同，再谈用它替换手写。预检进 Go 之后，控制面不必再靠仓库外的 Python 才能拒绝一份意图。`go.mod` 不加依赖。入口和 AI 的编译、Fabric 的批准、登记表的动态下发，这一步都不做：现在没有这三样的输入。

## 被考虑的替代方案

- **继续只手写，等第三家承运商再做编译器。** 2026-11-19 定过推后。2026-11-20 的开工许可把这一项包括进来。不选继续等。
- **编译器直接覆盖手写文件。** 没有采用。手写文件留着当黄金基线，编译结果与它们比。
- **预检仍只留 Python。** 不选。开发计划 4.3 写的是移植成 Go。脚本还在，契约测试仍用它的反例。

## 做出来了（V1.0）

2026-11-20，提交 `e78d62e`（25 个文件，没有外部依赖）。写代码、验证和执笔的是 AI 编码助手。**这不是对本 ADR 的决定**，状态保持 Proposed。

### 验证

- 两个构建：`gofmt` 干净，`go build`、`go vet`、`go test -count=1` 各 36 个包通过，`internal/architecture` 通过。
- 用真实的 `gateway-control` 和锁定的 agentgateway 1.7.0 `--validate-only`（`--lock-file`）编译两份 `compile-spec.json`，退出码都是 0，`native_validated` 为 true。`yaml.safe_load` 之后与手写的 `agentgateway.yaml` 相等，登记表 JSON 与手写的 `policy.example.json` 相等。万邦 4 条路由，顺丰 4 条路由，两家都是这样。
- 带 `frontend_limits` 和 `local_rate_limit` 的规格，通过 agentgateway 1.7.0 `--validate-only`。
- 四条对照：去掉只读存储；去掉后端授权前缀；预检放行 `127.0.0.1` 上游；`PROD` 上允许明文沙箱例外。每一条都有测试不通过，然后改回。
- 契约 231 项通过，安全 16 项通过。`tests/contracts/test_route_compiler.py` 不跑 Go，只核对规格和手写文件的字段对应。结构相等的证明在 `internal/routecompile` 的测试里。
- 这一提交没有重跑 compose 三轮：`tests/integration/compose/run.py` 构建 `gateway-control`，只跑 `publish`、`restart`、`reconcile`、`place` 和 `keep`；自 `78aee90` 以来 `cmd/gateway-control/main.go` 只在既有 switch 之前为 `sync-jwks` 和 `compile` 提前返回，`publish` 和 `keep` 的实现没有改，`gateway-authz` 的限流和 `provider-signer` 的熔断也不在这套路径上，[compose 套件 README](../../tests/integration/compose/README.md) 里已有的记录（30 个用例，一轮大约 750 秒，三轮）仍然有效，不被这次取代。
- 这个提交没有重跑黑盒。后来黑盒套件从干净的 `6c5659d` 重跑，证据由 `4416f89` 写入：97 个用例，96 个通过，751 项检查；唯一失败仍是已知的 `P1-SS-04`（两个 `Host` 头）。`--check-evidence` 打印 `OK p1-run-agentgateway-1.7.0.json (96/97 passed, commit 6c5659d)`。与 `149aa0e` 上的证据相比，没有一条用例、也没有一项检查在文字或结果上不同。文件起止是 2026-11-20T13:54:53Z 到 13:56:06Z，相差 72.5 秒；提交说明写用时 74.825 秒。

### 没有做的

- INGRESS 和 AI 的编译。预检覆盖这三类。编译只做出站。
- Fabric 的发布批准，和由批准过的 RouteIntent 去发布。
- `gateway-authz` 的登记表改由控制面下发。编译能写出登记表 JSON。没有动态推送。
- 手写的 `agentgateway.yaml` 和 `policy.example.json` 没有被编译产物换掉。

## 成本与剩余风险

- 编译规格和手写文件以后可能分叉。契约测试只对得上字段，对不上「编出来的字节与黄金文件结构相同」。后一条在 Go 测试里。
- 明文沙箱例外和池内签名器例外打开错了，会编出不该有的上游。`PROD` 拒绝明文沙箱。签名器那一条仍要 `VERIFY_REQUIRED` 和 `backend_tls`。
- 原生校验依赖本机有那份锁定的二进制，并且 SHA-256 对得上。对不上就不写输出文件。
