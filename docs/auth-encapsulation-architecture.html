§ 01

摘要与核心架构命题

核心结论：对常用外部认证方式进行封装并开放 UI 化配置高度推荐，但必须拒绝“把所有逻辑塞进单一系统”或“在 UI 中提供万能拼接脚本”的做法。科学边界是三方协同：认证执行引擎与编译护栏封装在 idp-gateway，路由与认证方案选择 UI 及审批发布落在 API Fabric，密钥只写录入与多租户账户授权归属 Gatekeeper（+ KMS）；idp-gateway 自带控制台仅保留只读审计与紧急撤销/封禁。

在取消独立 BIP 产品（ADR-0005）并确立统一 L7 出站网关（ADR-0004）后，CargoPai、Parcel、Brant、Prism 与 TELOS 等业务产品接入第三方承运商及 AI 上游时面临一对固有工程张力：若完全不封装认证，每接入一家新供应商都要修改网关代码与手工编写 YAML；若为了追求“全配置化”而在 UI 上开放任意 Header 模板或脚本表达式，则会直接破坏头白名单、方案前缀校验与密钥隔离防线。

Axiom 1 · 控制面解耦

声明配置在 Fabric，生效执行在 Gateway

Fabric 管理 API 资产、认证方案声明与发布审批（ADR-0006）；永不直接写代理原生 YAML，也不进入业务请求路径。

Axiom 2 · 凭密分离

配置只传引用，密钥只写不回显

路由与契约中仅携带 credential_binding_ref 句柄（ADR-0003），密钥明文永不进配置快照、环境变量或前端页面。

Axiom 3 · 80/20 分层

标准协议 UI 声明，非标算法代码封装

API Key / Bearer / Basic / OAuth2 / mTLS 做成标准模板（覆盖约 80%）；万邦随机数、顺丰密文信封沉淀为受测命名适配器（约 20%）。

§ 02

三系统职责边界与权威矩阵

大型 API 平台演进过程中最常见的架构退化是“双主事实（Split-Brain Authority）”——例如既在网关控制台配路由又在 Fabric 配路由，或在路由配置里直接存密钥明文。表 1 依据 ADR-0003、ADR-0006、ADR-0011、ADR-0016 与 ADR-0019 固化各系统在认证与发布全生命周期中的唯一权威归属。

生命周期能力 权威归属 交互方式 / 产物 明确禁令
认证方案选择与路由表单 UI API Fabric 用户在发布界面选 auth_scheme、填 Token URL / Scope / 超时并选 credential_binding_ref 禁止表单录入密钥明文或编写任意脚本表达式
发布审批与版本槽位 API Fabric 产出 RoutePublicationIntent（含 idempotency_key、release_ref、approval_ref） 禁止直接写网关数据库或把文档发布视作 ACTIVE
密钥录入、加密托管与轮换 Gatekeeper + KMS
过渡期：gateway-authz 0600		 只写不回显界面；产出句柄 gatekeeper:<id> 与 key_version 禁止前端回显明文；禁止密钥进入路由快照或环境变量
调用方认证与账户授权判定 Gatekeeper 签发 M2M JWT（专属 aud）并维护 ProviderAccount / ExternalAccessGrant 禁止将 JWT 认证通过直接等同于第三方账户授权
安全编译、预检与快照对账 gateway-control compile 输出受 1.7.0 校验的不可变快照；reconcile 核对 desired_digest 与 observed_digest 禁止绕过编译器手工注入动态路由或放宽安全头名单
运行时凭证兑现与上游注入 gateway-authz + agentgateway mTLS ExtAuthZ 按请求兑现 Bearer / OAuth2 / 开发者令牌，网关强制校验方案前缀 禁止跨账户复用 Token 缓存；禁止透传内部 IDP JWT
正文加密与非标签名改写 provider-signer 受限标准库适配器（固定操作表 + mTLS + 独立出口钉死 + 被动熔断） 禁止在网关核心加载任意脚本插件；禁止信任请求内目标地址
运行观测、紧急撤销与封禁 gateway-console 仅监听回环 IP；只读 0600 JSONL 审计；复用 revokerclient mTLS 执行撤销/封禁 禁止成为第二个路由发布入口或第二个用户口令表
工程注解：为何不再引入 Kong 或 Traefik？ 按 ADR-0001 与 ADR-0002，Ingress、Egress 与 AI 池已统一在锁定的 agentgateway 1.7.0 上并按安全域物理分池。多租户动态凭证注入、顺丰密文签名与即时撤销均位于 gateway-authz / provider-signer，Kong 与 Traefik 均无法替代；边缘仅需极简 50 行 front.nginx.conf 拦阻重复 Host 头（待上游含 PR #4401 的 OSS 正式版发布后再评估收敛）。叠加第二套代理只会引入双控制面与漂移风险。
§ 03

80/20 认证协议分层封装模型

认证封装的成败取决于抽象粒度。过度具体会导致代码爆炸，过度泛化（如在 UI 里开放自定义 Header 模板语言）则会摧毁安全审计边界。本规范按“协议标准化程度”与“正文改写复杂度”两个正交维度，将外部认证划分为两个受控层级与一个明确禁区。

交互式协议落位对照表（按方案切换查看三系统职责）

Tier 1 标准模板 适用于大多数 LLM 平台、REST SaaS 与静态凭证 API。

API Fabric UI
  • 选 auth_scheme = API_KEY
  • 配置投放位置：默认 authorization、允许头名或 credential_query_parameter
  • 配置方案前缀（如 Bearer ）并选择 credential_binding_ref
Gatekeeper / KMS
  • 只写表单录入 API Key 密文
  • 按租户/账户绑定 ExternalAccessGrant
  • 返回句柄（不回显 Key 内容）
IDP Gateway 编译与运行
  • compile 拒绝危险头名（cookie、x-idp-*、逐跳头）
  • 非 Authorization 位置自动改用 extauthz.credential + backendAuth 防夹带
  • 凭证经 ports.Secret 脱敏，零落日志

Tier 1 标准模板 遵循 RFC 6749 §4.4；仓内 internal/egressauthz/adapters/oauthclient 已完整实现。

API Fabric UI
  • 选 auth_scheme = OAUTH2_CLIENT_CREDENTIALS
  • 填写 token_url（强制 HTTPS）、scope_set、audience、token_ttl_max_seconds
  • 绑定 credential_binding_ref 与审批单号
Gatekeeper / KMS
  • 只写录入 client_id 与 client_secret
  • 维护 key_version 以支持即时轮换与旧缓存作废
  • 收回 Grant 后立即阻断该账户继续借用令牌
IDP Gateway 编译与运行
  • 复合缓存键隔离账户，并发取票 Singleflight 单飞
  • 提前刷新窗口 min(30s, TTL / 10)，取票超时 800ms
  • 撤销检查严格排在取票前；失败绝不复用过期令牌

Tier 2 命名适配器 对应 ADR-0011 第一步，已通过万邦速达真实沙箱与单机池联调。

API Fabric UI
  • 选固定类型 WANB_DEVELOPER_TOKEN
  • 仅需声明上游路径、允许方法、超时与凭证句柄
  • 无需且不允许手工拼装 Hc-OweDeveloper 字符串
Gatekeeper / KMS
  • 托管承运商 account 与开发者 token（严格 ASCII，禁分号与空白）
  • 不存随机数；换令牌走原子写临时文件再改名（过渡期）或 KMS 轮换
IDP Gateway 编译与运行
  • 每次放行用 crypto/rand 生成 16 字节 32 位十六进制随机数
  • 拼装 Hc-OweDeveloper 账号;令牌;随机数 注入上游
  • 路由后端规则强校验前缀 Hc-OweDeveloper

Tier 2 命名适配器 对应 ADR-0014，已通过顺丰国际 IECS 四条路由（含面单）沙箱联调。

API Fabric UI
  • 选固定类型 SF_INTL_ENVELOPE 并指定 request_signer_ref
  • 配置逻辑路径映射到固定 msgType 操作（如创建、取消、查询、面单）
  • 无需感知 AES 块填充与密文签名细节
Gatekeeper / KMS
  • 集中托管 app_key、app_secret、encoding_aes_key 与 key_version
  • 强约束：同一 app_key 仅允许绑定单一句柄，防多处换票互踢
IDP Gateway 编译与运行
  • gateway-authz 取票并下发 Sf-OpenApi 复合凭证
  • 网关 mTLS 转发明文 JSON 至 provider-signer
  • 签名器查固定操作表 → AES-256-CBC 加密 + SHA-256 签名 → 独立命名空间出口发出 → 解密验 appKey 后回传明文
§ 04

零信任形式化判定与双路径运行时注入

依据 docs/G04_Identity_and_Security.md 第 0 节与第 3 节，任何外部 API 调用必须严格分离三道不可混淆的安全门禁：调用方身份认证（Caller Authentication）、多租户账户授权（Access Authorization）与上游供应商认证（Upstream Authentication）。

Formal Zero-Trust Decision Predicate (G04 §3)
ALLOW = TrustedCaller ∧ AudienceValid ∧ TenantBound ∧ ActiveGrant ∧ ProviderAccountActive ∧ EnvironmentMatch ∧ OperationAllowed ∧ RouteAllowlisted ∧ CredentialAllowed ∧ NoExplicitDeny FAIL-CLOSED AXIOM: Decision ∈ { UNKNOWN, INDETERMINATE } ⇒ DENY (HTTP 403 / 503)

OAuth2 令牌生命周期与多租户缓存隔离数学约束

对于 OAUTH2_CLIENT_CREDENTIALS 模板，多租户串号（S-03）与撤销窗口泄漏是最危险的故障模式。internal/egressauthz/adapters/oauthclient 按 G04 §4 与 ADR-0011 强制执行三项不变量：

OAuth2 Isolation & Refresh Invariants
CacheKey = ( provider_id, account_id, environment, client_id, scope_or_audience, key_version ) RefreshLead(L) = min( 30s, L / 10 ) // 到期前提前换新；并发请求 Singleflight 合并为 1 次上游取票 Revocation : RevocationCheck(account) ≺ CredentialSource(account) // 已被撤销账户绝不触发缓存读取
§ 05

编译器反夹带护栏与安全底线

即便用户在 Fabric UI 中只做结构化选项，配置一旦进入数据面仍须通过 gateway-control compile 的静态与原生校验（ADR-0016）。尤其在支持自定义凭证头（如 X-API-Key）或查询参数时，必须防范一类隐蔽的凭证夹带漏洞（已在锁定 agentgateway 1.7.0 上实测证实）。

面向 UI 化配置的三大不可妥协底线与威胁缓解矩阵

三条架构红线（任何 UI 或 API 迭代均不得突破） 1. 密钥零入快照：编译器静态拒绝 ${...} 与 $VAR 环境变量引用；所有凭证字段在内存经 ports.Secret 封装，错误/日志/JSON 序列化均输出占位符。
2. 敏感头强清洗：请求入站固定剔除 9 个敏感/伪造头（x-provider-account、cookie、x-forwarded-*、forwarded、x-idp-verified-*）；响应剔除 location、set-cookie、x-idp-decision-id。
3. 失败默认拒绝：禁止自动跟随 302 重定向、禁止对非幂等写操作自动重试、禁止回滚配置覆盖高优撤销表（ADR-0012）。
